  1. AWSWrites go to the writer The app uses the cluster endpoint. aurora-shopnow-dev-1 saves to the volume.
  2. AWSWriter and reader share one volume One cluster volume keeps 6 copies across 3 AZs. The reader sees the same data.
  3. AWSReads go to the reader endpoint aurora-shopnow-dev-2 answers reads, and takes over if the writer fails.
  4. AzureWrites go to the primary replica appdb is Hyperscale, 2 vCores. Entra-only sign-in, through a private endpoint.
  5. AzurePage servers hold the data A log service feeds the page servers. All replicas share them, up to 128 TB.
  6. AzureRead-only connections use the HA replica Add ApplicationIntent=ReadOnly to the connection string to read from it.
  7. Google CloudWrites go to the primary instance alloydb-shopnow-dev, instance primary. Its IP comes from the step 06 range.
  8. Google CloudAll instances share one storage layer The primary writes once. The read pool reads that same storage.
  9. Google CloudReads go to the read pool read-pool-1 (1 node, 2 vCPU) has its own IP. Send read-only queries there.
